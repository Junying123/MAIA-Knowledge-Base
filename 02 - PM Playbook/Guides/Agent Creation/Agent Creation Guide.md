Example:\n\n> \"From a raw discovery transcript, extract pain points and fill the Requirement Gathering template.\"\n\n### 2️⃣ Prepare the Context\n\nGather everything the agent needs to know and place it in a temporary folder or as variables you will pass via the wrapper:\n\n- **Input files** (e.g., raw transcript, GTM brief).\n- **Reference files** (e.g., the empty template, any related SOPs).\n- **Instructions** (a short prompt that tells the agent exactly what to do).\n\nTip: Keep the context under a few thousand tokens so the agent stays focused.\n\n### 3️⃣ Choose the Agent\n\nMatch the task strength to the agent:\n\n| Task Type | Best Agent | Why |\n|-----------|------------|-----|\n| Complex reasoning, synthesis, extraction | **Claude Code** | Strong at understanding long transcripts and structuring information. |\n| Structured output, code‑like generation, lists, tables | **Codex** | Excellent at producing formatted markdown, JSON, tables, user stories. |\n| File‑ops, templating, batch updates, checks | **Goose** | Great at copying templates, validating completeness, updating metadata. |\n| Long‑running review, consistency scans, diffing | **OpenCode** (free) | Can run longer sessions without cost, good for style/consistency checks. |\n| Quick polish, language fixes, formatting | **Pi** | Fast, lightweight, ideal for cleaning up client‑facing text. |\n\n### 4️⃣ Build the Wrapper Command\n\nThe wrapper expects:\n\n```bash\n~/.hermes/agent-wrappers/route.sh <agent-name> \"<prompt>\"\n```\n\n- `<agent-name>` is one of `claude-code`, `codex`, `goose`, `opencode`, `pi`.\n- `<prompt>` is the full instruction you want the agent to follow, including any file paths or variables.\n\n**Example – Claude Code filling an RG template:**\n\n```bash\n~/.hermes/agent-wrappers/route.sh claude-code \"\\\nRead the raw transcript at ~/Documents/MAIA Knowledge Base/03 - Clients/We're cooked discovery/Requirement Gathering/Ming Medical/Meeting Notes/2026-04-23-Ming Medical-Requirements-Gathering.md\\\nand extract the answers to the standard clarifying‑question set (problem, workaround, expected outcome, users/transactions, priority).\\\nThen, using the template at ~/Documents/MAIA Knowledge Base/02 - PM Playbook/Templates/[Template] Requirement Gathering.md,\\\nfill in every section (business context, current vs desired state, expected behavior, acceptance criteria, priority/urgency, dependencies).\\\nFinally, apply the triage SOP at 09 - Intake & Triage/Triage SOP (Product vs Config vs Custom) to classify the requirement and add a classification block at the top of the output.\\\nSave the finished document as Requirement Gathering – Ming Medical – 2026-04-23.md in the same folder as the transcript.\"\n```\n\n### 5️⃣ Run the Agent\n\nExecute the command in your terminal. The wrapper will spawn the agent in an isolated runtime, feed it the prompt, and return the final output (usually a file write or stdout).\n\n### 6️⃣ Review & Iterate\n\n- Check the produced file for correctness and completeness.\n- If anything is missing or incorrect, refine the prompt and run again (the agent can be re‑invoked with updated context).\n- Use Goose or OpenCode to run a quick completeness/consistency check if needed.\n\n### 7️⃣ Finalise & Link\n\nOnce the output is satisfactory:\n\n- Ensure the file is saved in the appropriate location (usually `03 - Clients/<Client>/Requirement Gathering/` or the relevant sub‑folder).\n- Add a link from the client’s main folder or from the RG output’s front‑matter if needed.\n- If the output reveals a gap, create an entry in `04 - QA & Known Issues/Feature Gap Tracker`.\n- Send a brief confirmation message to the client (via Lark/WhatsApp) summarising what was captured and ask for validation.\n\n### 8️⃣ Document the Process (Optional)\n\nIf this workflow will be reused, save the exact wrapper command and context description as a **Skill** (using `skill_manage`) or add a note to `02 - PM Playbook/Guides/Agent Creation/` for future reference.\n\n## Best Practices\n\n- **Keep prompts specific**: Include exact file paths, expected section headings, and any required formats (e.g., \"Use checkboxes `- [ ]` for action items\").\n- **Limit scope per run**: One agent run should accomplish a single, well‑defined transformation. Chain multiple runs via Hermes if you need several steps.\n- **Leverage the KB**: Always read from and write back to the MAIA KB so the work is traceable and version‑controlled.\n- **Validate before moving on**: Use Goose (completeness) or OpenCode (consistency) as a gate before handing off to the next agent or to a human.\n- **Client confirmation**: After each major step, send a short summary to the client and obtain acknowledgment to avoid misunderstandings.\n- **Version control**: Commit changes to the KB regularly (use `git mv` for moves, commit with a short imperative message).\n\n## Example End‑to‑End Flow (Requirement Gathering)\n\n1. Hermes starts a live transcription (Granola) or loads an existing transcript.\n2. Claude Code reads the transcript and produces a structured Q&A log.\n3. Goose copies the RG template into the client’s WIP folder.\n4. Claude Code fills the template using the Q&A log and adds the classification block.\n5. Goose runs a completeness check; if missing items are reported, Hermes asks Claude Code to fix them.\n6. (Optional) OpenCode runs a consistency check on acceptance criteria and priority formatting.\n7. Hermes links the final RG output to the client folder, creates a gap‑tracker entry if needed, and sends a validation message to the client.\n8. Based on the classification, Hermes either creates a User Story (via Codex) or a Config spec (via Goose) and notifies the owner.\n\n## See Also\n\n- [[02 - PM Playbook/Guides/Multi-Agent Orchestration for PM]] – the overall agent architecture.\n- [[02 - PM Playbook/Processes/Requirement Gathering Process]] – the SOP this guide helps automate.\n- [[02 - PM Playbook/Templates/[Template] Requirement Gathering]] – the empty template to fill.\n- [[09 - Intake & Triage/Triage SOP (Product vs Config vs Custom)]] – classification logic.\n- [[04 - QA & Known Issues/Feature Gap Tracker]] – where to log discovered gaps.\n\n---\n*Maintained by Gareth (PM & Hermes Orchestrator)*\n
