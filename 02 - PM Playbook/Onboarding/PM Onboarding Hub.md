# PM Onboarding Hub

## We Are Building a Shared Brain

The MAIA PM team works across clients, features, and sprints — and the hardest part of doing that well isn't the work itself, it's the context. Who knows the Acme Corp integration history? Which PM wrote the invoice user stories last quarter? Why did we decide against that approach three months ago?

The answer to all of these should be: **the KB**. Not someone's memory. Not a Slack thread from six weeks ago.

This onboarding is not about learning tools. It is about joining a shared way of working — where knowledge lives in one place, everyone contributes, and the team gets smarter with every sprint.

---

## What You Are Setting Up

| Tool | What It Is | Why You Need It |
|------|-----------|----------------|
| **Obsidian** | Local Markdown editor | Opens the shared KB vault — your knowledge home |
| **This KB** | Shared team knowledge base | Templates, workflows, product docs, client context — all in one place |
| **Cursor** | AI-powered editor | AI assistant that reads your KB files — not generic internet advice, but MAIA-specific output |

These three tools work together:
- **Obsidian** is where you read and write KB content
- **The KB** is the content itself — the shared product brain
- **Cursor** is the AI that reads the KB to help you produce PM outputs faster

---

## Why We Built This

### Problems this solves

| Old reality | New reality |
|-------------|-------------|
| Re-explaining the same client context every time a PM rotates | Client folder in `03 - Clients/` — everything in one place |
| "Where is the user story template again?" — asked in Slack weekly | Open `[[Quick Reference]]` — it's the second item |
| Every PM's PRDs look different | One canonical template, AI uses it by default |
| New PM takes 2–3 weeks to be productive | KB + this onboarding = productive in 2 days |
| Knowledge walks out the door when someone leaves | It doesn't, because it was never in their head alone |
| Copy-pasting context into ChatGPT every time | Cursor reads your KB files directly |

### What will actually be faster for you

- **Writing user stories:** 2 hours → 20 minutes (AI + template)
- **Drafting a PRD:** Half a day → 45 minutes (AI + template + client context already in KB)
- **Preparing a req gathering session:** 30 min from scratch → 10 minutes (AI reads client history)
- **QA scenario writing:** 1 hour → 15 minutes (AI + template + known limitations doc)
- **Ramping up on a new client:** Days of questions → open their folder and read

---

## Your Role

You are not just a reader of this KB. You are a contributor.

Every time you add a meeting note, update a client folder, improve a template, or document a bug — the whole team benefits. The KB is only as good as the team that maintains it.

**Minimum expectation:** Keep your client folders current. If you learn something about a client, add it.

**Good contribution:** When you write a useful user story or req doc, save a copy to the KB as an example for future PMs.

**Great contribution:** When you discover something is wrong or missing in the KB, fix it or raise it with Gareth.

## First-Week Checklist

Work through these in order. Each item links to a guide.

### Day 1 — Get Set Up

- [ ] Read [[01 - Setup Obsidian]] and install Obsidian
- [ ] Open the shared KB vault (follow [[KB GitHub Sync — How It Works]])
- [ ] Navigate to this page (`PM Onboarding Hub`) — you're already here
- [ ] Open [[Quick Reference]] and bookmark it (right-click the tab → Pin)
- [ ] Read [[02 - Using This KB]] — understand folder structure and conventions

### Day 2 — Set Up Your AI Assistant

- [ ] Read [[03 - Setup Cursor AI]] and install Cursor
- [ ] Open the vault folder in Cursor
- [ ] Enable Claude model in Cursor settings
- [ ] Run the first test: summarise the Glossary page using AI

### Day 3 — Use the Combined Workflow

- [ ] Read [[04 - AI + KB Workflow for PMs]] — understand the core loop
- [ ] Bookmark [[05 - AI Prompt Library for PMs]] — your go-to prompt reference
- [ ] Pick one real task from your current work (a user story, meeting notes, or req summary)
- [ ] Complete it using AI + KB, save the output back to Obsidian

### End of Week 1

- [ ] Find one thing that is wrong or missing in the KB — fix it or raise it with Gareth
- [ ] Add or update something in your assigned client folder
- [ ] Message Gareth with any questions or feedback on the onboarding
