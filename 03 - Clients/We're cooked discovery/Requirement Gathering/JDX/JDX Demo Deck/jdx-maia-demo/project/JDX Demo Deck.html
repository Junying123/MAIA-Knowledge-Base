Create Order + Pro Forma Invoice
Pain today
  • Accounts assistant manually creates pro forma in SQL
  • Customisation remarks typed as free text — no structure
  • No central order log across channels
MAIA solves it
  • Create SO — customer, items, qty, customisation remarks (ribbon colour, greeting card, delivery date, price tag on/off)
  • Pro Forma Invoice PDF generated instantly
  • Sent to customer directly from MAIA
Web AppSales Workspace → Create SO → Generate PDF → Pro Forma Invoice
WhatsApp"Create order for [customer], [item], [qty]" → add remarks → send pro forma
2Demo Step 2 of 5
Payment Confirmation + Invoice Conversion
Pain today
  • Customer sends payment slip to WhatsApp group
  • Coordinator manually matches slip to pro forma
  • Coordinators stay up overnight during peak season
MAIA solves it
  • Coordinator attaches payment slip to the order in MAIA
  • One-click: Pro Forma → Invoice conversion
  • All line items, remarks, and customer details carry through automatically
Web AppFinance Workspace → attach payment slip → Convert to Invoice
WhatsApp"Convert SO-0001 to invoice" → attach slip → receipt created
3Demo Step 3 of 5
Customisation Remarks — Entered Once, Used Everywhere
Pain today
  • Same remarks retyped or copy-pasted at every handoff
  • Pro forma → DO → warehouse → ops — details drop along the way
  • Warehouse repacks too late due to missing instructions
MAIA solves it
  • Remarks entered once at the Sales Order
  • Automatically flow: SO → Invoice → Delivery Order → Warehouse view
  • No retyping. No copy-paste. No WhatsApp forwarding.
Presenter note: Show the remarks field on the SO only. Do NOT click through to Invoice or DO.
Say: "This is built for JDX in Phase 1. When configured, remarks carry through automatically to the DO and warehouse view — we won't demo it live today."
4Demo Step 4 of 5
Multi-Drop Delivery — One Order, Many Destinations
Pain today
  • One corporate order = 50+ delivery addresses on a spreadsheet
  • No live view — failed deliveries handled by phone
  • No record of reschedules or failed attempts
MAIA solves it
  • One SO → multiple DOs (Blanket Order); each DO has its own date and status
  • All drops linked to source SO — viewable in one place
  • Schedule, track, and update each drop independently
Web AppLogistics Workspace → create multiple DOs from one SO → each with own date and status
WhatsApp"Split SO-0001 to 3 DOs: 20/15/15" → MAIA confirms DOs created
5Demo Step 5 of 5
Delivery Status Tracking — Live, Per Drop
Pain today
  • Coordinator scrolls WhatsApp to match driver photos to drops
  • Failed deliveries rescheduled by phone — no record kept
  • No morning visibility on what's scheduled vs pending
MAIA solves it
  • Each DO: To Schedule → Scheduled → Completed / Failed
  • Mark delivered, failed, or reschedule via web app or WhatsApp
  • Daily Digest every morning: Pending / Scheduled / Completed
  • Alert when DO not scheduled after X days from invoice
Web AppLogistics Workspace → update DO status → view all drops for one order
WhatsApp"Mark DO-001 as delivered" → Daily Digest preview
