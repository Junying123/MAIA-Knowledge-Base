# Onboarding Guide

## Purpose
This guide helps a new team member get oriented in the MAIA product environment.

Use this document to understand:
- what this repo is for
- which repos matter
- who the key people are
- where to start reading

## What This Repo Is
`maia-product` is the MAIA product team's working context repo.

It is meant to reduce context loss by keeping important operational, product, and team knowledge in a structured place.

## Start Here
Read these files first:
1. `README.md`
2. `CLAUDE.md`
3. `docs/mindhive-company-context.md`
4. `docs/repo-map.md`
5. `docs/ways-of-working.md`
6. `docs/source-of-truth-matrix.md`

## Key Repos To Know
- `maia-product`: product-team context, onboarding, templates, operating docs
- `maia-codex`: formal implementation and product specification source of truth
- `maia-chatbot-middleware`: chatbot and middleware implementation
- `mindhive_erpnext_apis`: ERP API layer and backend-related integration surface
- `maia-sync-spine`: sync, data movement, and integration-related backend work

See `docs/repo-map.md` for more detail.

## Key People To Know
See `docs/mindhive-company-context.md` for the current team structure.

At a minimum, a newcomer should know:
- Gareth: product team
- Ivan: product and tech lead
- Jermaine: CTO
- Jeremy: GTM lead

## How Work Usually Flows
At a high level:
1. A request or need appears.
2. Product context is gathered.
3. Scope is clarified.
4. Formal implementation context moves into MAIA CODEX when ready.
5. Delivery is coordinated across product, tech, and business teams.

See `docs/ways-of-working.md` for the fuller version.

## What To Update As You Learn
If you discover missing context, update the relevant place instead of keeping it in chat only:
- team structure -> `docs/mindhive-company-context.md`
- repo ownership or purpose -> `docs/repo-map.md`
- terminology -> `docs/glossary.md`
- key decisions -> `docs/decision-log.md`
- process changes -> `docs/ways-of-working.md`

## First-Week Goal
By the end of onboarding, a newcomer should be able to answer:
- what each main MAIA repo is for
- who leads product, tech, and GTM
- where implementation specs live
- where team context and reusable delivery context live
